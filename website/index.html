Purpose · Wegmann Step 1

Why hunt for the ground that didn't burn

Warming climate, a fire-primed Canterbury, and a legacy of cleared land now carrying gorse — the reasons this landscape burns, and why a vegetation map is the tool that lets us read it.

The driver

A warming, drying east coast

Fire weather is lengthening across eastern Aotearoa New Zealand. Hotter, drier summers push more days over the ignition threshold on the Port Hills. 📖 WMO

The fuel

Gorse on cleared land

A century of clearance left exotic grassland and dense, oily gorse & broom — fast-drying, highly flammable fuel — sitting next to native scrub and pine. What grows where decides what burns. 📖 Wyse

The tool

Why a classification map

A satellite only hands us reflectance numbers. Only a classification attaches a vegetation label to every pixel — and only then can we line up what burned against what grew there, and find the refugia. 📖 Meddens

The fire from space · before → during → after

Four satellites, one fire

No single satellite tells the whole story. An optical camera sees colour but not through smoke; radar sees through cloud but not colour; a thermal sensor catches the flames themselves. Reading the Port Hills fire meant using four of them together — each with its own strength and its own blind spot.

How these were made — the GEE recipe GEE · Python · reproducible

Every image above comes from two openly-searchable collections. The core calls, so anyone can reproduce them for any area and date:

import ee; ee.Initialize(project='genuine-hold-427410-f0')
aoi = ee.Geometry.Rectangle([172.55, -43.65, 172.67, -43.56])

# DURING — Sentinel-2, ignition day (13 Feb)
s2 = (ee.ImageCollection('COPERNICUS/S2_SR_HARMONIZED')
      .filterBounds(aoi).filterDate('2017-02-13', '2017-02-14').first())
true_colour = s2.select(['B4', 'B3', 'B2'])     # natural colour
swir_glow   = s2.select(['B12', 'B8', 'B4'])    # SWIR -> active fire glows

# dNBR — Landsat 8, pre (8 Feb) vs post (24 Feb)
def nbr(ic):
    img = ic.median().select('SR_B.').multiply(0.0000275).add(-0.2)
    return img.normalizedDifference(['SR_B5', 'SR_B7'])  # (NIR-SWIR2)/(NIR+SWIR2)
L8   = ee.ImageCollection('LANDSAT/LC08/C02/T1_L2').filterBounds(aoi)
dnbr = nbr(L8.filterDate('2017-02-01', '2017-02-11')) \
     .subtract(nbr(L8.filterDate('2017-02-24', '2017-03-30'))).multiply(1000)

Reuse: change aoi and the dates and this reproduces natural-colour, SWIR and dNBR for any fire with Landsat / Sentinel-2 coverage. For radar, swap in COPERNICUS/S1_GRD, band VH, pre- vs post-fire.

3a · Smart cloud-shadow mask

Burn scar ≠ shadow

Fresh char is spectrally dark — almost indistinguishable from cloud shadow to an automatic QA flag. A naïve mask therefore deletes exactly the pixels that burned hardest. The fix: mask cloud everywhere, but keep the "shadow" flag only outside the fire perimeter. Inside, dark means char, not shadow.

00_A1_PortHills_dNBR.js — smart mask GEE · JavaScript · reusable

The QA logic, straight from the source. Cloud (bit 3) is masked everywhere; shadow (bit 4) is masked only where the pixel is not inside the fire.

// QA_PIXEL bits: 3 = cloud, 4 = cloud shadow
function maskL8clouds_QA(image) {
  var qa = image.select('QA_PIXEL');
  var inFire = ee.Image.constant(1).clip(aoi).mask();
  var bad = qa.bitwiseAnd(1 << 3).neq(0)            // cloud: everywhere
    .or(qa.bitwiseAnd(1 << 4).neq(0).and(inFire.not())); // shadow: outside only
  return scaleSR(image).updateMask(bad.not());
}

Reuse: swap aoi for any fire perimeter and this keeps char inside while still cleaning cloud — works for any Landsat C2L2 burn where fresh scar is being lost to shadow flags.

3b · Seasonal-drift offset

Making dNBR = 0 mean "nothing changed"

Unburnt vegetation should read dNBR = 0. But the pre- and post-fire composites are weeks apart, so seasonal and atmospheric drift push it off zero. A control ring around the fire (inner 500 m, outer 2 km), matched to the fire's own elevation and slope range, with Dynamic World excluding cropland and water, gives the true baseline — subtracted from the whole scene.

26_A1_python_port_get_numbers.py — the real numbers GEE · Python · reproducible

A direct Python port of the A1 JavaScript compute steps, written so the numbers that only ever lived in the GEE console (offset, threshold, refugia area) become reproducible output anyone can re-run.

# control ring matched to the fire on elevation, slope, cover
ring = aoi.buffer(2000).difference(aoi.buffer(500), 1)
ctrl = dnbrRaw.updateMask(controlMask).reduceRegion(
    reducer=ee.Reducer.mean().combine(ee.Reducer.stdDev(), None, True),
    geometry=ring, scale=30, maxPixels=1e9)
offset = ee.Number(ctrl.get('dNBR_mean'))   # → 83.6 (per-class: trees 65 / shrub 84 / grass 119)
dnbr   = dnbrRaw.subtract(offset)           # now 0 = no change

3c · Outliers · every cell in the study area

A few patches don't look like the rest — do we throw them out?

We looked at all 18,581 cells (each 30 × 30 m). Most look alike; a few stand out. The real question isn't "are they weird" — it's "are they a mistake, or real ground?" Every odd one here turns out to be real: dense broadleaf/gorse scrub, bright bare soil, deep shade, or steep cliffs. So we keep them and just label them — throwing away real ground would only hide the truth.

The decision: keep every one, just label it. None are sensor errors — they're real forest, soil, shade and cliffs. Deleting real ground would bias the results, so we flag instead. (Same rule as the dark-char cells earlier: flag, don't delete.)

Relationships · R4

What predicts how hard a pixel burned

Correlation, regression, and an honest test of a state-of-the-art alternative. The headline: pre-fire greenness and bare soil pull hardest — and the answer is robust to the method you choose, with one telling exception.

Correlation with dNBR (burn severity). Toggle the method: only pre_B4 changes its significance verdict — every other variable keeps its rank and sign. Values shown are point-based; the whole-grid correlation table is pending. 🤖 04e

Linear regression · whole grid

R² = 0.23

Across the whole 30 m grid (spatially thinned, ~1,000 cells), pre-fire spectral + terrain variables explain R² = 0.23 of burn-severity variation — modest, and honest. An earlier point-based 0.41 was inflated by a small sample sitting in polygon cores (at n ≈ 64 it jumps to 0.46). Residuals still carry spatial structure (Moran's I 0.63 at 120 m), so GWR is the next step. A second layer — adding FuelClass on the reference cells to test ΔR² — is pending.

VIF cleanup: raw bands hit VIF 47–99. Iterative dropping settled on 6 variables (pre_B2, pre_B5, NDMI, elev, slope, northness), all VIF ≤ 7.5.

SOTA check, honestly reported

RBR vs dNBR — no improvement

RBR (Parks 2014) relativises dNBR by pre-fire biomass, and our fuels span bare rock to dense pine — exactly its design case. Run side by side: RBR R² = 0.304 vs dNBR 0.322. It did not help. We report that and keep dNBR. (point-based; grid rerun pending.) 📖 Parks 2014 🤖 04f

Classification · R5

Mapping the fuels that carried the fire

A Random Forest over four vegetation fuel classes, trained on 2015 aerial photo-interpretation and spatially blocked so validation can't cheat. Where the model struggles, the separability analysis already predicted it would.

Before supervision · k-means probe

"Can we even tell native scrub from gorse?"

Before training any classifier, unsupervised k-means asked whether the vegetation types are separable at all. It flagged the gorse_broom ↔ broadleaf_scrub overlap right at the start — the same pair the 6-band JM (only 0.79) would later put a number on, and the same pair the final confusion matrix confirms. The worry was earned, not incidental.

The confusion isn't the model's fault

The biggest misclassification — broadleaf_scrub ↔ gorse_broom — lands exactly on the pair the 6-band JM (0.79, the weakest pair) flagged as spectrally inseparable. The accuracy ceiling here is a real property of the vegetation, not a modelling error, and the report says so.

What Gini couldn't tell us

Slope is pasture's hidden signal

slope ranks 7th globally by Gini importance — easy to dismiss. But split by class, it's the number-one feature for pasture (flat ground = paddock). Averaging across four classes drowned it out.

pre_B4 (red) is the top global variable, but SHAP shows its sign flips: strongly positive for pasture (+0.94 — bright grass), negative for the other three. A single importance number hides that entirely.

The core finding · R7

The refugia the official map never drew

This is the finding the whole project was for. Using two hand-drawn unburnt islands as an independent reference, a defensible threshold separates burnt from unburnt — and then finds far more unburnt ground than anyone mapped by eye.

Way forward · R6

How far this method travels

The pipeline doesn't depend on this particular fire. Here's what transfers as-is, and the specific data that — based on what was actually missing here — would push it further.

Transferable as-is

The pipeline

Landsat 8 composite (cloud mask + scaling) → LCDB + aerial labels, with cleared_pine defined by Hansen forest-loss ∩ vegetation polygon (change-data instead of spectral guessing — works for any Hansen-covered forest fire) → 15 m pixel-purity check (half a Landsat pixel; drops straight into any 30 m task) → spatial-block split (kills spatial autocorrelation) → exploration, regression, RF → wall-to-wall classify + clip to true perimeter → refugia × vegetation × terrain. None of it is Port-Hills-specific.

What would help — and by how much

The missing data

Sentinel-2 red-edge & spring imagery → lifts the gorse/broadleaf JM from 0.79 to 1.45 and gorse recall from 41% to 49%, and unlocks a full-year phenology series (2016 had a clean image every month). 🤖 grid
Pre-fire LiDAR (CHM + texture) → literature shows ~14% accuracy gain; the best shot at the gorse↔broadleaf confusion.
More post-fire revisits → 16 of 19 cleared_pine points hit cloud; more satellites = fewer lost pixels.
Fine-scale fuel-moisture / wind fields → station data is too uniform across a few km²; a modelled field would add a variable class that's currently absent.
